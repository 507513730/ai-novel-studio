## 结论

有实际问题，不只是文案过时。发布状态误报、门禁顺序、证据归属和互相冲突的操作指引都可能导致错误交付。本轮仅修流程、CI、测试工具与活跃文档，不新增业务功能。

## 方向重做 500 的定位

同样两个接口、同样默认 flash 模型：网关首次方向生成成功（42149ms），重做记录 upstream-timeout 后返回 500；官方备用初次 10017ms、重做 15440ms 均成功。此次已确认走到上游超时失败路径，没有依据归咎于本地 JSON 替换算法。

对照仅是定向诊断，不是完整生产验证；脏工作区证据不会被发布脚本接受。完整 E2E 必须另跑，实际 provider 进入证据。界面通用 500 的可诊断性仍可后续改善，本轮未扩大到业务错误模型重构。
