# 备份与恢复

> 数据目录约定：安装版 = 系统用户数据目录；便携版 = exe 同级 `data/`（与 server、备份、清除数据统一）。

## 自动备份

- 每日自动：由独立服务生成一致性快照到 `backups/auto-日期时间/`，轮转保留最近 7 份受管备份。夹带其他文件或清单无效的目录不会被自动清理。
- 设置页展示最近备份时间与份数。

## 手动导出

- 「设置 → 导出备份」：选择一个尚不存在的目标目录 → 服务执行 SQLite 一致性快照 → 收到成功确认后写入 `backup-info.json`。已存在目录一律拒绝覆盖，不清空其中内容。
- 快照为独立主库文件，包含生成快照时已提交的数据，不依赖源库 WAL 是否 checkpoint。
- 失败或超时的目录保留 `backup-in-progress.json` 标记，不能用于恢复；重新导出时请选择新的目录。

## 从备份恢复

1. 「设置 → 从备份恢复」选择完整备份目录（或其中的 `ai-novel-studio.db` 文件）；未完成备份和无效目录会被拒绝，不会自动改选父目录。
2. 版本不一致时会提示确认。应用先复制到暂存目录，独立校验数据库完整性与应用结构，并尝试升级旧格式；损坏、非本应用或未来数据库版本会被拒绝，原数据保持不变。
3. 校验通过后关闭原服务并保留原库；新服务在后台任务暂停时启动，确认可用后才提交恢复并刷新页面。
4. 新服务启动失败会尝试恢复原库并重启原服务。切换中断时，下次启动先处理未完成恢复；如果恢复记录损坏或文件仍无法访问，应用会提示数据目录并退出，保留文件供处理，不保证手动重启能解决所有故障。
5. 最近一次成功恢复前的原库保存在数据目录 `restore-随机编号/before/`，含 `backup-info.json`，可通过同一恢复入口选择该目录回退。后续成功恢复会清理更旧的受管副本；夹带未知文件或失败轮次的目录保留供诊断。

以上恢复加固为本地待发布改动；正式安装版是否包含该能力，以后续 Release 说明为准。

## 升级前快照

应用更新需要数据库迁移时，会在数据目录的 `backups/` 中尝试保存迁移前副本，然后迁移当前数据库。该旧机制不等于本节的恢复事务，也不保证迁移失败自动回退；重要数据升级前请使用手动导出备份。

## 清除全部数据

「设置 → 清除数据」：先优雅关闭 server（释放数据库句柄）→ 删除数据目录 → 退出。需要二次确认，不可撤销。
