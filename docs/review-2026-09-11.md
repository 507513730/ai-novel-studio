## 硬规范修订（用户已批准并生效）

下列“原文”保留初筛时 AGENTS.md 的历史措辞；四项建议已获用户批准并写回 AGENTS.md，对应机制同步到协作者手册。

### 提案 1：#36 产物名称随当前版本解析

原文：“必须执行 `pnpm dist` 同步重建 `release\AI-Novel-Studio Setup 0.1.0.exe`（NSIS）与 `release\AI-Novel-Studio-0.1.0-portable-x64.exe`（portable），确认两个产物时间戳已更新”。

建议：“任何代码改动完成后执行 `pnpm dist`，根据 package.json 当前版本及 build.nsis/build.portable 的 artifactName 模板确认两类产物；记录时间戳与 SHA-256。候选包与正式 Release 资产分别报告，打包失败不算交付完成。”

原因：固定 0.1.0 路径与当前模板不符，可能检查旧文件或误报缺失；包哈希能绑定验证证据，时间戳单独不能证明包内容。

### 提案 2：#48 一致快照、恢复校验与回退

原文：“备份 = 复制 db 三件套到目录（含 backup-info.json）；恢复必须校验 db 存在 → 替换 → 退出；恢复/清除前必须 ConfirmDialog。”

建议：“备份使用服务进程内一致性快照协议及完成清单，不跨进程复制活跃库。恢复/清除保留 ConfirmDialog 与操作互斥；恢复前在独立临时副本验证数据库完整性与应用结构，拒绝未完成或不兼容备份。关闭服务并确认退出后，保留原数据库与关联文件，再替换；失败时恢复原文件，回退失败须保留可恢复副本并明确报错。”

原因：D129 已采用 VACUUM INTO 快照，旧文字鼓励回到不一致复制；“存在”不等于有效数据库，多文件替换失败需要明确恢复责任。本条是机制提案，具体支持范围须与本批实际实现及测试对齐。

### 提案 3：#62 按 SHA 验证 CI，禁止重指正式 tag

原文：“src 变更必须同批通过全部 CI，禁止只过本地三绿就 push”；以及“`--force-with-lease` 推送，并同步重指 tag”。

建议：“本地门禁和候选版本一致性通过后推送源码 SHA，等待该 SHA 的必需 CI 全绿；失败由推送者修复，以新 SHA 重新验证。正式发布仅消费通过门禁的 SHA。已发布 Release 的 tag 不删除、不强制移动；公开提交消息需修正时优先新增说明或修正提交，未发布历史是否重写另行授权。”

原因：远端 CI 需要先收到 SHA 才能验证，不能要求尚未推送的提交已通过其 CI；重指已发布 tag 与 #51 不可重复/force tag 的约束冲突，也破坏产物与源码关联。

### 提案 4：#62 命令与 pnpm 专用纪律统一

原文：“提交前用 `npx commitlint --from <base> --to HEAD --verbose` 自验”，以及末尾的 `npx commitlint` 示例。

建议：“提交前用 `pnpm exec commitlint --from <base> --to HEAD --verbose` 自验；若工具未在依赖中，先明确安装方案，不由命令隐式下载。”

原因：npx 示例与 #3 pnpm 专用纪律冲突；pnpm exec 使用项目已安装工具，命令与依赖来源更可复核。
