## 已修复

### S1：IPC 校验混淆顶层祖先与发送者（高优先级）

原 isTrustedSender 检查 senderFrame.top === mainFrame。子 frame 的 top 同样指向主 frame，不能证明发送者本身是顶层；缺失 senderFrame 也被放行。改为主窗口 webContents 与 senderFrame === mainFrame 双重校验，窗口尚未注册时 token 通道同样 fail-closed。window.ts 在加载页面前注册主窗口，不依赖启动期豁免。

测试补全同窗口父子关系、缺失/null frame、启动期 token 拒绝、合法主 frame 放行。该问题是校验逻辑缺陷；本次没有宣称已完成实际 XSS 到 IPC 的可利用链验证。

### S2：导航白名单使用字符串前缀（高优先级）

原开发态 startsWith(devUrl) 会放行端口前缀伪装或 userinfo URL；原打包态放行任意 file URL，不限本应用页面。现在开发态比较 HTTP(S) origin，拒绝用户名/密码；打包态只允许实际 renderer/index.html，保留 hash/search。非法 URL fail-closed。

## 待处理发现（尚未修复）

1. **备份导出递归删除用户所选现有目录**：electron/ipc.ts 的 export-backup 在 existsSync(outDir) 后 rmSync(outDir, recursive)，没有验证目录是否只包含本应用备份。应禁止覆盖非备份目录，拒绝数据目录及其祖先；在临时目录构造哨兵文件回归，不能拿真实目录做实验。
2. **checkpoint 失败被当成成功**：electron/shutdown.ts 的 requestCheckpoint 在 timeout、checkpoint-error、无服务时均 resolve；调用方继续复制主库。server/src/index.ts 的 checkpoint 应答也未检查 pragma 返回状态。下一批需设计可证明一致的备份快照协议，加入错误、超时、并发写入测试，不只修注释或延长等待。
3. **写作偏好缺少操作防重**：client/src/pages/settings/WritingPanel.tsx 的 patch 没有 busy 守卫，重叠请求可能让本地显示与数据库最终值不一致；需串行化或明确 latest-write 语义并测试乱序完成。

5. **模型调用后续深审**：caller.ts 的流式输出在已发 delta 后失败仍可能换候选，需核对 onDelta 消费者是否清空上一尝试；此项只是风险线索，尚未完成复现。
